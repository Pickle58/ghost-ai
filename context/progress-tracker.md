## Current Goal

- A signed-in owner or collaborator can connect nodes with custom right-angle edges that are easy to follow and click. Unselected nodes hide the toolbar.

Edges stay dimmed at rest and brighten when hovered or selected. A 32px invisible hit area makes them easier to click. Double-clicking an edge edits its label in `EdgeLabelRenderer` at the path midpoint. Saved labels render as pill badges. An unlabeled selected edge shows a faint "Label" hint. Blur, Enter, and Escape save through `updateEdgeData`. Label pointer events use `nodrag`, `nopan`, and `nowheel`. The in-progress connection line uses SmoothStep and the same stroke.

## Architecture Decisions

- Generated `components/ui/*` files stay as installed. Dark theme alignment lives in `app/globals.css`.
- The app is dark only. `:root` and `.dark` use the same palette, and `<html>` carries the `dark` class so component `dark:` styles apply.
- shadcn uses the `base-nova` style (Base UI). `cn()` is the `cn` package, re-exported from `lib/utils.ts`.
- Editor chrome lives in `components/editor`. `EditorShell` owns sidebar open state. The project sidebar is absolutely positioned over the canvas, so opening it does not change canvas layout. `EditorDialog` applies theme tokens for title, description, and footer actions. `components/ui/dialog.tsx` stays unmodified.
- Project dialog state and mutations live in `hooks/use-project-actions.ts`. The create dialog previews a room ID from `toRoomId`: the slugified name plus a 6-character suffix. That room ID is the project ID and the Liveblocks room ID. `POST /api/projects` accepts this id when it matches the room ID shape; omitted ids still use the schema UUID default. A taken id returns 409. Slugs are not a separate column.
- Project metadata lives in PostgreSQL through `src/prisma/db.ts`. `ownerId` stores the Clerk user ID. `canvasJsonPath` is the blob reference and stays empty until canvas storage exists.
- Project mutations check `id` and `ownerId` together. A miss is then classified: no row is 404, a row owned by someone else is 403. Lists are newest `createdAt` first, then `id`. Rename rejects a missing or blank name. Create accepts a room ID only when the caller sends one; otherwise the schema UUID default still applies. The caller cannot set `ownerId`.
- Workspace access is decided in `lib/project-access.ts`. The identity is the Clerk user id plus a verified email: the verified primary address, otherwise another verified address. A missing project and a project the user cannot access both render `AccessDenied`. The AI sidebar is an overlay placeholder, same as the project sidebar, so it does not resize the canvas.
- Collaborator emails are trimmed and lowercased before they are stored or matched. Invite and remove check `ownerId` on the server. Listing is allowed for the owner or a matching collaborator. Names and avatars come from Clerk at read time and are not stored. A Clerk address is used for that profile only when its verification status is `verified`. An invite of the owner's own verified email is rejected because that person already has access. Invite emails are Clerk application invitations (`notify: true`). The link uses Clerk's sign-up path, and `<SignUp>` already sends new users to `/editor`, where a matching collaborator email opens the shared project. Access is stored even when Clerk cannot send the email, and the dialog says so. Inviting an address that already has access sends the email again.
- The Liveblocks room id is the project id. Rooms are created private, with no default access. A session grants write access only to that one id, and only after `getAccessibleProject` allows the caller. The room id must match `isRoomId`, so the token cannot carry a wildcard. The display name is the Clerk full name, then the username, then `Anonymous`. The avatar is attached only when it is an https URL. Cursor color comes from a fixed palette hashed from the Clerk user id. The Node client is cached on `globalThis`.
- The canvas client mounts only after the workspace server page has allowed the room. `useLiveblocksFlow` stores the diagram in Liveblocks under the default `flow` key, starting from empty nodes and edges. Presence includes `isThinking: false` because the Presence type requires it. `types/canvas.ts` defines `canvasNode` and `canvasEdge`, plus `NODE_COLORS`, `NODE_SHAPES`, and `DEFAULT_NODE_SIZES`. Rectangles are wider than tall, circles are square, and diamonds are larger than circles so a label has room. New nodes are created with an `add` change so Liveblocks stores them. `canvasNode` and `canvasEdge` are both registered. The shape toolbar is not a drop target. Canvas snapshots are still not written.
- Rectangle, pill, and circle are CSS. Diamond, hexagon, and cylinder are inline SVGs in a 100×100 viewBox with `preserveAspectRatio="none"`, so the geometry fills the node box. Stroke width stays constant with `non-scaling-stroke`. Placed nodes set `pointer-events: all` on that SVG so the whole node box can be grabbed. The drag ghost uses the same graphic, centered on the pointer, sized to the default node size times the current canvas zoom, with pointer events off so the preview is not the drop target. It does not change the drop payload or how nodes are created.
- Node resize uses a React Flow resize control on each corner of the selected node. Side handles are connection points and stay hidden until hover, so a selected node shows corner resize dots until the pointer is over it. Dimension changes already flow through `onNodesChange` into Liveblocks width and height. The minimum size is 64×48 in `MIN_NODE_SIZE`, which is below every default shape size. The resize handles are 6px light circles. Label edits call `updateNodeData`, which emits a replace change on that same handler. The label stays in a centered overlay. While editing, the textarea occupies that overlay, and pointer events inside it do not drag or pan. Shape graphics, the shape panel, the drag ghost, and drop creation are unchanged.
- Each shape has four source handles, one at the middle of each side, sitting on the border. They are 6px white dots with a `--bg-base` border, hidden until the node is hovered, then faded in. Corner handles still resize. `ConnectionMode.Loose` lets any handle connect to any other handle. New connections merge `defaultEdgeOptions` into Liveblocks `onConnect`, so stored edges are `canvasEdge` with a closed arrow, rounded 1px stroke, and `data.label`. The custom renderer draws a smooth-step path from `getSmoothStepPath`, dims the stroke to `--text-muted` at rest, and brightens to `--text-primary` when hovered, selected, or being labeled. `BaseEdge` uses a 32px interaction width. Labels sit in `EdgeLabelRenderer` at the path midpoint coordinates. `updateEdgeData` writes `data.label` through the same Liveblocks edge changes as node data. The in-progress line is SmoothStep with that same stroke.
- Node color uses the eight `NODE_COLORS` pairs in `types/canvas.ts`. The collaborative field is still `data.color` (the fill). Text comes from `nodeTextColor`. A selected node mounts `NodeToolbar` 12px above the node, with one swatch per pair. The active swatch uses a 1.5px ring in that pair's text color. Hover glow is a 4px shadow in the same text color. Toolbar chrome uses elevated surface tokens. Shape creation, resize, labels, and connections are unchanged.
